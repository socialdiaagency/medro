# MedRo — One Medical World

منصة مجتمع طبي احترافية (عربي / English): منشورات وحالات وأسئلة مع صور (حتى 4 صور) وصور شخصية، أصدقاء، مجموعات عامة ومجموعات جامعية موثقة بمشرف، وظائف، إعلانات بين المنشورات، سجل طبي خاص لكل مستخدم، توثيق بموافقة الأدمن، مركز إشعارات، مساعد طبي بالذكاء الاصطناعي، ولوحة أدمن تتحكم في كل شيء (حتى نصوص الصفحة الرئيسية).

- **الواجهة:** موقع ثابت (HTML + CSS + JavaScript) بدون خطوة بناء. يُستضاف مجانًا على GitHub Pages.
- **الباك إند:** Supabase (قاعدة PostgreSQL + تسجيل دخول + لحظي + تخزين الصور) على الخطة المجانية.
- **الذكاء الاصطناعي:** دالة Edge Function تتصل بـ Google Gemini (مجاني) أو Anthropic. المفتاح السري على الخادم فقط.

> **وضعان للتشغيل بنفس الملفات**
> - `config.js` فارغ ← **وضع تجريبي**: بيانات وهمية تُحفظ في متصفح كل زائر (للتجربة والعرض فقط).
> - `config.js` فيه بيانات Supabase ← **وضع حقيقي**: حسابات وبيانات مشتركة، وصلاحيات محمية على مستوى قاعدة البيانات.

## 3) خطوات التثبيت بالتفصيل

### الخطوة 1 — إنشاء مشروع Supabase
1. ادخل https://supabase.com/dashboard ثم **New project**.
2. **Name:** `medro` — **Database Password:** كلمة مرور قوية (احفظها في مكان آمن) — **Region:** أقرب منطقة لجمهورك (لمصر: أوروبا مثل Frankfurt أو London غالبًا الأسرع).
3. اختر الخطة **Free** ثم **Create new project**، وانتظر دقيقة أو دقيقتين حتى يكتمل التجهيز.
4. احتفظ بـ **Project ref**: هو الجزء الذي في رابط لوحة التحكم `https://supabase.com/dashboard/project/<PROJECT_REF>`.

### الخطوة 2 — إنشاء الجداول وسياسات الأمان
1. من القائمة اليسرى: **SQL Editor** ← **New query**.
2. افتح الملف `supabase/schema.sql` من هذا المشروع، انسخ محتواه **كاملًا**، والصقه في المحرر.
3. اضغط **Run**. يجب أن تظهر رسالة نجاح (مثل `Success. No rows returned`).
4. تحقق: **Table Editor** يعرض نحو 20 جدولًا (والصور في Storage) (`profiles`, `posts`, `groups`, `notifications`…).

> الملف آمن لإعادة التشغيل لو احتجت تحديثه لاحقًا. لا يحذف بياناتك.

### الخطوة 2-ب — تفعيل رفع الصور (Storage)
1. **SQL Editor ← New query**، انسخ محتوى `supabase/storage.sql` كاملًا والصقه، ثم **Run**.
2. تحقق: **Storage** في القائمة اليسرى يعرض حاوية اسمها `media` بحالة **Public**.
3. ينشئ الملف أيضًا حاوية ثانية اسمها **`private`** بحالة **Private** (لصور البطاقة والصورة الحيّة وإيصالات الدفع الخاصة بقسم الاستشارات الطبية). لا يقرأها إلا صاحبها والأدمن، والأدمن يراها عبر روابط موقّعة تنتهي بعد 5 دقائق.
4. ما يفعله الملف للحاوية `media`: ينشئ الحاوية بحد أقصى **3MB للملف** وأنواع صور فقط، ويسمح لكل مستخدم بالرفع داخل مجلده فقط (`media/<user-id>/...`)، والحذف لصاحب الملف أو الأدمن.
5. لو ظهر خطأ صلاحيات على `storage.objects`: أنشئ السياسات الثلاث (select / insert / delete) من **Storage ← Policies** بنفس الشروط الموجودة في الملف.

> الصور تُضغط داخل متصفح المستخدم قبل الرفع (أقصى بعد 1600px للمنشورات و384px للصور الشخصية بصيغة JPEG)، وتُحذف بيانات الموقع (EXIF) تلقائيًا. الصور الشخصية والصور داخل المنشورات تُحذف من التخزين عند حذف صاحبها لها أو حذف المنشور أو حذف الحساب من لوحة الأدمن.

### الخطوة 3 — إعدادات تسجيل الدخول (Authentication)
1. **Authentication ← Sign In / Providers** (أو **Providers**) ← تأكد أن **Email** مفعّل.
2. خيار **Confirm email**:
   - **للتجربة السريعة:** عطّله، فيدخل المستخدم مباشرة بعد التسجيل.
   - **للإطلاق الحقيقي:** أبقه مفعّلًا. لكن الإيميل الافتراضي من Supabase محدود جدًا في عدد الرسائل، فاربط خدمة SMTP خاصة (مثل Resend أو Brevo، ولهما خطة مجانية) من **Authentication ← SMTP Settings**.
3. **Authentication ← URL Configuration**: ضع في **Site URL** رابط موقعك على GitHub Pages (ستعرفه في الخطوة 7، يمكنك العودة لهذه الخطوة بعدها)، وأضفه أيضًا في **Redirect URLs**.

### الخطوة 4 — مفتاح الذكاء الاصطناعي (Gemini المجاني)
1. ادخل https://aistudio.google.com/apikey ← **Create API key**.
2. انسخ المفتاح (سنضعه في الخطوة 5 كسر على الخادم، **ولا يوضع أبدًا في ملفات الموقع**).

### الخطوة 5 — نشر دوال الخادم (Edge Functions)

**الطريقة (أ): بالـ CLI — الأدق (موصى بها)**

افتح الطرفية داخل مجلد المشروع ونفّذ:

```bash
npx supabase@latest login
npx supabase@latest link --project-ref <PROJECT_REF>

# أسرار الدالة (تبقى على الخادم)
npx supabase@latest secrets set GEMINI_API_KEY=ضع_مفتاحك_هنا

# نشر الدالتين (بدون verify-jwt لأن الدالتين تتحققان من المستخدم داخليًا)
npx supabase@latest functions deploy ai --no-verify-jwt
npx supabase@latest functions deploy admin --no-verify-jwt
```

**الطريقة (ب): من لوحة التحكم بدون CLI**

1. **Edge Functions ← Deploy a new function ← Via Editor**.
2. الاسم `ai`، والصق محتوى `supabase/functions/ai/index.ts`، ثم **Deploy**.
3. من إعدادات الدالة عطّل خيار **Verify JWT**.
4. كرّر نفس الشيء للدالة `admin` بملف `supabase/functions/admin/index.ts`.
5. أضف السر: في صفحة **Edge Functions** افتح **Secrets** ← **Add new secret** ← الاسم `GEMINI_API_KEY` والقيمة مفتاحك.

**أسرار اختيارية** (بنفس الطريقة):

| السر | الوظيفة | الافتراضي |
|---|---|---|
| `AI_MODEL` | اسم النموذج | `gemini-2.5-flash` (أو `claude-haiku-5-5` مع Anthropic) |
| `AI_PROVIDER` | `gemini` أو `anthropic` | تلقائي حسب المفتاح الموجود |
| `ANTHROPIC_API_KEY` | استخدام Anthropic بدل Gemini | — |
| `AI_DAILY_LIMIT` | عدد أسئلة المساعد يوميًا لكل مستخدم عادي (الأدمن مستثنى) | `40` |
| `MEDRO_SECRET_KEY` | مفتاح `sb_secret_...` — تحتاجه فقط لو لم تتوفر `SUPABASE_SERVICE_ROLE_KEY` تلقائيًا في بيئة الدوال | — |

> أسماء النماذج تتغير مع الوقت. لو ظهرت رسالة أن النموذج غير موجود، راجع القائمة الحالية في توثيق Gemini وضع الاسم الصحيح في `AI_MODEL`.

### الخطوة 6 — ربط الموقع بمشروعك (`config.js`)
1. في Supabase: **Project Settings ← API Keys** (أو زر **Connect** أعلى الصفحة).
2. انسخ:
   - **Project URL**: شكلها `https://xxxxxxxx.supabase.co`
   - **Publishable key** (يبدأ بـ `sb_publishable_`) — أو مفتاح **anon** القديم (يبدأ بـ `eyJ`).
3. افتح `config.js` وضعهما:

```js
window.MEDRO_CONFIG = {
  SUPABASE_URL: "https://xxxxxxxx.supabase.co",
  SUPABASE_ANON_KEY: "sb_publishable_xxxxxxxxxxxxxxxx"
};
```

> هذا المفتاح **عام بطبيعته** ومحمي بسياسات RLS، فلا مشكلة في رفعه على GitHub. أما `secret` و`service_role` فممنوع وضعهما في أي ملف من ملفات الموقع.

**بديل بدون تعديل الملف:** في المستودع على GitHub: **Settings ← Secrets and variables ← Actions ← Variables** أضف `SUPABASE_URL` و`SUPABASE_ANON_KEY`، وسيكتب النشر التلقائي `config.js` لك.

### الخطوة 7 — الرفع على GitHub ونشر الموقع
1. أنشئ مستودعًا جديدًا على https://github.com/new باسم `medro` (اجعله **Public**) بدون README.
2. من الطرفية داخل مجلد المشروع:

```bash
git init -b main
git add .
git commit -m "MedRo first release"
git remote add origin https://github.com/<اسم-حسابك>/medro.git
git push -u origin main
```

3. على GitHub: **Settings ← Pages ← Build and deployment ← Source: GitHub Actions**.
4. افتح تبويب **Actions** وانتظر نجاح تشغيل **Deploy MedRo to GitHub Pages**.
5. موقعك سيكون على: `https://<اسم-حسابك>.github.io/medro/`
6. ارجع للخطوة 3 وضع هذا الرابط في **Site URL** و**Redirect URLs**.

> **GitHub Pages مع مستودع خاص (Private)** يتطلب خطة مدفوعة. إن أردت مستودعًا خاصًا مجانًا استخدم **Cloudflare Pages** أو **Netlify** أو **Vercel**: اربط المستودع، **بدون أمر بناء**، ومجلد النشر هو الجذر `/`.

### الخطوة 8 — اجعل نفسك أدمن
1. افتح الموقع وأنشئ حسابًا ببريدك (ثم أكّد البريد إن كان التأكيد مفعّلًا).
2. في Supabase **SQL Editor** شغّل (بعد استبدال البريد ببريدك):

```sql
update public.profiles
set role = 'admin'
where id = (select id from auth.users where email = 'you@example.com');
```

3. سجّل الخروج ثم الدخول. ستجد **لوحة الأدمن** في القائمة الجانبية.

### الخطوة 9 — اختبار سريع (5 دقائق)
- [ ] الصفحة الرئيسية تظهر بالشعار وتحميل MR، والوضع الليلي والتبديل عربي/English يعملان.
- [ ] إنشاء حساب ثانٍ (من نافذة خاصة في المتصفح) ونشر منشور؛ يظهر عند الحساب الأول بعد التحديث.
- [ ] نشر منشور بصورتين، ثم تغيير الصورة الشخصية من **تعديل الملف الشخصي**؛ تظهر الصور عند الحساب الآخر، والنقر على الصورة يكبّرها. (تأكد في **Storage ← media** من ظهور مجلد باسم معرّف المستخدم.)
- [ ] إعجاب وتعليق ← يصل إشعار للطرف الآخر على الجرس فورًا.
- [ ] **لوحة الأدمن**: تبويب **الموقع** (شريط إعلان ومفاتيح تشغيل المزايا)، **النصوص**، **المجموعات** (إنشاء مجموعة جامعية وتعيين مشرف)، **الإعلانات**، **التوثيق**.
- [ ] المساعد الطبي يرد (لو لم يرد راجع قسم الأخطاء).
- [ ] حساب جديد يطلب الانضمام لمجموعة جامعية ← المشرف يوافق.

## 4) كيف يعمل الأمان؟

- **كل الصلاحيات الحقيقية في قاعدة البيانات (RLS)** وليست في الواجهة. حتى لو عدّل أحدهم JavaScript في متصفحه لن يستطيع تجاوزها.
- المستخدم لا يستطيع ترقية نفسه لأدمن أو توثيق نفسه أو رفع الحظر (triggers + سياسات).
- **السجل الطبي** يقرؤه صاحبه فقط (حتى الأدمن لا يقرؤه). **البريد الإلكتروني** وأرقام التراخيص يراها صاحبها والأدمن فقط.
- المجموعات الجامعية: الانضمام بطلب يوافق عليه المشرف أو الأدمن، ومحتواها لا يظهر لغير الأعضاء.
- **الصور:** الخادم نفسه يفرض الحد (3MB) وأنواع الصور ومجلد المستخدم؛ والواجهة لا تعرض إلا صورًا من تخزين مشروعك (تمنع روابط التتبع الخارجية). **تنبيه خصوصية:** الحاوية عامة، فمن يملك رابط الصورة يفتحها حتى لو المنشور داخل مجموعة خاصة. الروابط طويلة وغير قابلة للتخمين، لكن لا تنشر صورًا حساسة. الصور لا تُفحص بالذكاء الاصطناعي؛ المحتوى المخالف يُبلَّغ عنه ويحذفه الأدمن.
- المفتاح السري للذكاء الاصطناعي لا يظهر في المتصفح؛ ولكل مستخدم حد يومي.
- عدّادات الإعلانات (مشاهدات/نقرات) عبر دالة آمنة `ad_hit` ولا يستطيع المستخدم كتابتها مباشرة.
- حسابات المحظورين لا تستطيع الكتابة.
- **حظر مستخدم لمستخدم:** من ملف أي عضو (أو قائمة المنشور) → «حظر». الحظر متبادل في العرض: لا يرى أحدهما منشورات/تعليقات/إعجابات الآخر، ولا يستطيع إرسال طلب صداقة أو إشعار له، وتُحذف الصداقة بينهما. الطرف المحظور **لا يُبلَّغ** بالحظر (يرى فقط أن الملف غير متاح). قائمة الحظر خاصة بصاحبها (حتى الأدمن لا يراها)، ولا يمكن حظر الأدمن. الأدمن ومشرفو المجموعات يرون محتوى المجموعة كاملًا لأغراض الإشراف. الحظر يُنفَّذ في قاعدة البيانات (جدول `user_blocks` + دالة `blocked_between`)؛ **أعد تشغيل `schema.sql` كاملًا** عند الترقية.

**آلية الحفظ:** الواجهة تحتفظ بنسخة من البيانات وتقارنها دوريًا بآخر حالة محفوظة، ثم ترسل للخادم الفروق فقط (إضافة/تعديل/حذف). لو رفضت قاعدة البيانات أي تغيير بسبب الصلاحيات، تظهر رسالة وتُعاد البيانات من الخادم.

## 5) حدود الخطة المجانية (راجع الصفحات الرسمية للأرقام الحالية)

- **Supabase Free:** قاعدة بيانات بحجم محدود (حوالي 500MB وقت كتابة هذا الدليل)، وعدد مستخدمين نشطين شهريًا كبير يكفي البداية. **المشاريع غير النشطة لأسبوع تُوقف مؤقتًا** (Pause) ويمكنك تشغيلها من لوحة التحكم. لا يوجد نسخ احتياطي تلقائي يومي في الخطة المجانية؛ صدّر نسخة دورية من **Database ← Backups** أو بـ `pg_dump`.
- **Gemini المجاني:** حدود طلبات في الدقيقة واليوم، وقد تُستخدم المحادثات في الخطة المجانية لتحسين منتجات Google حسب شروطهم الحالية. **راجع الشروط، ونبّه المستخدمين ألا يكتبوا بيانات مرضى تعريفية** (واجهة المنصة تذكّرهم بذلك). للاستخدام الجاد انتقل لخطة مدفوعة أو مزوّد بسياسة خصوصية مناسبة.
- **التخزين:** الخطة المجانية فيها حصة تخزين محدودة (حوالي 1GB وقت كتابة الدليل) وحد لحجم النقل الشهري؛ الضغط يجعل الصورة غالبًا أقل من 500KB. راقب الاستهلاك من **Project Settings ← Usage**.
- **التحميل:** الواجهة تجلب أحدث 300 منشور وتعليقاتها. للأعداد الكبيرة سنضيف ترقيم صفحات لاحقًا.

## 6) استكشاف الأخطاء

| العَرَض | السبب والحل |
|---|---|
| الموقع يعمل بالبيانات الوهمية رغم أني ملأت `config.js` | تأكد من نسخ الرابط والمفتاح بدون مسافات، وأن الملف المرفوع هو المعدّل (حدّث الصفحة بـ Ctrl+Shift+R). افتح Console (F12) وابحث عن أخطاء. |
| `permission denied for table …` | لم يُشغَّل `schema.sql` كاملًا. شغّله مرة أخرى. |
| `Invalid login credentials` | بريد أو كلمة مرور خاطئة، أو الحساب لم يُؤكَّد بعد. |
| لا تصل رسالة تأكيد البريد | حد الإيميل الافتراضي. اربط SMTP أو عطّل Confirm email مؤقتًا. |
| "تعذّر حفظ آخر تغيير" | رفضت قاعدة البيانات العملية. افتح Console وستجد السبب (غالبًا صلاحية). تأكد أن حسابك أدمن لو كانت عملية إدارية. |
| `new row violates row-level security policy` عند رفع صورة | لم يُشغَّل `storage.sql`، أو المستخدم محظور، أو ملف غير مسموح. |
| الصورة لا تظهر رغم نجاح الرفع | تأكد أن حاوية `media` **Public** وأن `SUPABASE_URL` في `config.js` هو نفس مشروع الرفع (لا تُعرض إلا الصور من نفس المشروع). |
| `column "images" does not exist` أو `"avatar"` | شغّل `schema.sql` مرة أخرى (يضيف الأعمدة الجديدة للمشاريع القديمة). |
| المساعد الطبي لا يرد، الخطأ `ai_not_configured` | لم يُضَف `GEMINI_API_KEY` في أسرار الدوال. |
| الخطأ `rate_limited` | وصل المستخدم للحد اليومي (`AI_DAILY_LIMIT`) أو حد مزوّد الذكاء الاصطناعي. |
| الخطأ `ai_failed` | راجع **Edge Functions ← ai ← Logs**؛ غالبًا اسم نموذج خاطئ أو مفتاح غير صالح. |
| إضافة/حذف مستخدم من لوحة الأدمن يفشل | الدالة `admin` غير منشورة، أو حسابك ليس أدمن. راجع Logs. |
| الموقع لا يفتح بعد فترة | قد يكون مشروع Supabase في حالة Pause. شغّله من لوحة التحكم. |
| صفحة 404 على GitHub Pages | تأكد من اختيار **Source: GitHub Actions** ونجاح تشغيل الـ workflow. |

## 8) تطبيق أندرويد (Google Play)

**الفكرة:** التطبيق هو نفس واجهة الموقع داخل غلاف أندرويد (Capacitor). يتصل **بنفس مشروع Supabase**: نفس الحسابات والبيانات والصلاحيات والدوال، فلا شيء يتغير في الباك إند. ما يتغير: ملفات الواجهة تُحزَّم داخل التطبيق، فأي تعديل في التصميم يحتاج بناء نسخة جديدة ورفعها (بعكس الموقع الذي يتحدث فور رفعه على GitHub).

> **صدق في التقدير:** هذا الجزء كُتب واختُبر منطقه (حذف الحساب، زر الرجوع، سكربتات التجهيز، Service Worker) لكن **لم يُبنَ ملف APK فعليًا** في بيئة التطوير لعدم توفر Android SDK والإنترنت هناك. أول تشغيل لـ workflow البناء قد يحتاج تعديلًا بسيطًا لو تغيّر قالب Capacitor؛ رسائل الخطأ في سكربتات التجهيز مكتوبة لتدلّك على السبب.

### المتطلبات قبل البدء
- الموقع يعمل ومربوط بـ Supabase (الخطوات 1–9 أعلاه) **ومستودع GitHub عام** (البناء على Actions مجاني للمستودعات العامة).
- **أعد نشر دالة `admin`** لأنها تحتوي الآن على حذف المستخدم لحسابه (مطلوب من Google Play):
  ```bash
  npx supabase@latest functions deploy admin --no-verify-jwt
  ```
  (أو الصق `supabase/functions/admin/index.ts` الجديد في محرر الدالة بلوحة Supabase ثم Deploy).
- حساب مطوّر في Google Play (رسوم تسجيل لمرة واحدة؛ راجع الرقم الحالي داخل Play Console).

### أ) إعدادات قبل أول بناء
1. افتح `config.js` وضع بريد الدعم واسم الجهة (يظهران في صفحتي الخصوصية وحذف الحساب):
   ```js
   APP_OPERATOR: "SOCIALDIA AGENCY",
   SUPPORT_EMAIL: "support@your-domain.com"
   ```
2. **اسم الحزمة** `com.socialdia.medro` في `capacitor.config.json` (appId). غيّره الآن لو أردت اسمًا آخر، لأنه **لا يمكن تغييره بعد أول رفع على Google Play**.
3. ارفع التعديلات على GitHub (`git add . && git commit -m "android" && git push`) وانتظر نجاح نشر الموقع، فتصبح الصفحتان متاحتين على:
   - `https://<اسم-حسابك>.github.io/medro/privacy.html`
   - `https://<اسم-حسابك>.github.io/medro/delete-account.html`

### ب) إنشاء مفتاح توقيع التطبيق (مرة واحدة)
على جهازك (يلزم Java؛ أو استخدم الطرفية في Android Studio):
```bash
keytool -genkeypair -v -keystore upload.jks -alias medro -keyalg RSA -keysize 2048 -validity 10000
```
- اكتب كلمة مرور قوية، واحفظ **الملف `upload.jks` وكلمة المرور في مكان آمن** (لا ترفعه على GitHub؛ `.gitignore` يمنعه).
- حوّله إلى نص Base64:
  - Linux / macOS: `base64 -w0 upload.jks`  (على macOS: `base64 -i upload.jks`)
  - Windows PowerShell: `[Convert]::ToBase64String([IO.File]::ReadAllBytes("upload.jks"))`
- في GitHub: **Settings ← Secrets and variables ← Actions ← Secrets ← New repository secret**، أضف:

| الاسم | القيمة |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | ناتج Base64 أعلاه |
| `ANDROID_KEYSTORE_PASSWORD` | كلمة مرور الملف |
| `ANDROID_KEY_ALIAS` | `medro` |
| `ANDROID_KEY_PASSWORD` | كلمة مرور المفتاح (إن كانت نفسها اترك الخانة فارغة أو أعد كتابتها) |

> لو فقدت هذا المفتاح لاحقًا: مع Play App Signing (الافتراضي) يمكن طلب إعادة ضبط مفتاح الرفع من دعم Google، لكن احتفظ بنسخة احتياطية.

وتأكد أن المتغيرين `SUPABASE_URL` و`SUPABASE_ANON_KEY` موجودان إما في `config.js` أو في **Variables** (الخطوة 6). البناء يتوقف برسالة واضحة لو كانا فارغين، أو لو وُضع مفتاح سري بالخطأ.

### ج) بناء التطبيق
1. على GitHub: **Actions ← Build Android app ← Run workflow**.
2. اكتب **اسم الإصدار** (مثل `1.0.0`) و**رقم الإصدار** (رقم صحيح يزيد مع كل رفع جديد على Google Play؛ اتركه فارغًا ليستخدم رقم التشغيل).
3. بعد 5–10 دقائق افتح التشغيل الناجح ونزّل الملف **medro-android** من قسم Artifacts. بداخله:
   - `medro-debug.apk` — للتجربة على أي هاتف.
   - `medro-release.aab` — للرفع على Google Play (يكون موقّعًا لو أضفت الأسرار؛ وإلا يظهر باسم `...-UNSIGNED.aab` ولا يقبله Google Play).

### د) تجربة التطبيق على هاتفك
انقل `medro-debug.apk` للهاتف وافتحه (فعّل «التثبيت من مصادر غير معروفة» لتطبيق الملفات أو المتصفح). هذا الملف موقّع بمفتاح اختبار ويصلح للتجربة وتوزيعه على قلة من المختبرين، لا للنشر العام.

### هـ) النشر على Google Play
1. **Play Console ← Create app**: الاسم MedRo، اللغة العربية، النوع App، مجاني.
2. **App content** (محتوى التطبيق) وأهم ما يُطلب:
   - **Privacy policy:** رابط `privacy.html` أعلاه.
   - **Data safety:** صرّح بالبيانات التي يجمعها التطبيق: الاسم والبريد، الصور، الرسائل/المحتوى الذي ينشئه المستخدم، المعلومات الصحية (السجل الطبي الاختياري)، وأنها تُشفَّر أثناء النقل (HTTPS)، وأن المستخدم يستطيع طلب حذفها.
   - **Account deletion:** أدخل رابط `delete-account.html`. التطبيق نفسه فيه الزر: الملف الشخصي ← تعديل الملف الشخصي ← «حذف حسابي». ([شرح سياسة Google](https://support.google.com/googleplay/android-developer/answer/13327111))
   - **Ads:** اختر أن التطبيق يحتوي إعلانات (إعلانات المنصة التي يضيفها الأدمن).
   - **Target audience:** 18 سنة فأكثر (أو 16+ حسب اختيارك)؛ ليس موجّهًا للأطفال.
   - **Health / Content rating / User-generated content:** أجب عن النماذج الظاهرة لك بدقة. المنصة فيها إبلاغ عن المحتوى وحذف وحظر من الأدمن؛ راجع سياسة المحتوى الذي ينشئه المستخدمون الحالية عند التعبئة، ويُنصح بإضافة «حظر مستخدم» لاحقًا.
   - الرد الطبي بالذكاء الاصطناعي: ذكّر في وصف التطبيق أنه للتثقيف وليس تشخيصًا.
3. **اختبار مغلق (Closed testing):** [الحسابات الشخصية التي أُنشئت بعد 13 نوفمبر 2023](https://support.google.com/googleplay/android-developer/answer/14151465) تحتاج **12 مختبرًا على الأقل ثابتين في الاختبار 14 يومًا متتاليًا** قبل زر «Apply for production». أنشئ مسار Closed testing، ارفع `medro-release.aab`، وأضف المختبرين بقائمة بريد. (الصفحة الرسمية لا تذكر هل ينطبق ذلك على حسابات المؤسسات؛ اسأل دعم Google.)
4. بعد الموافقة: **Production ← Create release**، ارفع AAB جديدًا وأرسله للمراجعة.
5. **التحديثات:** عدّل الواجهة ← ارفع على GitHub ← شغّل Build Android app برقم إصدار **أكبر** ← ارفع AAB الجديد.

### و) ما يعمل وما لا يعمل في التطبيق حاليًا
- ✔ نفس الحسابات والبيانات والإشعارات اللحظية (والتطبيق مفتوح)، رفع الصور من المعرض، الوضع الليلي، العربية/English، زر الرجوع في أندرويد، فتح الواجهة بدون إنترنت (البيانات تحتاج إنترنت).
- ✔ حذف الحساب من داخل التطبيق ومن صفحة الويب.
- ✘ **إشعارات الدفع (Push) والتطبيق مقفول:** غير مضافة بعد (تحتاج Firebase). الإشعارات تظهر داخل التطبيق فقط.
- ✔ الكاميرا (للصورة الحيّة في طلب الطبيب): الصلاحية تُضاف تلقائيًا لملف الـ Manifest وسيطلبها أندرويد من المستخدم عند أول استخدام.
- رابط تأكيد البريد يفتح في المتصفح لا في التطبيق؛ بعد التأكيد ارجع للتطبيق وسجّل الدخول (أو عطّل Confirm email وقت التجربة).

## 10) الاستشارات الطبية أونلاين (الأطباء، الحجز، الدفع، العمولة)

قسم **«للاستفسارات الطبية»** يتيح لأي عضو مسجّل حجز كشف أونلاين عند طبيب **اعتمده الأدمن**. القسم **مغلق افتراضيًا** في الوضع الحقيقي حتى تفعّله بنفسك (انظر التفعيل أدناه).

### الأدوار والشارات
- التسجيل الجديد **لا يتيح اختيار «طبيب»** ولا أي لقب طبي: كل من يسجّل يصبح **«عضو»** (شارة رمادية صغيرة بجوار الاسم). يمكنه تعديل تخصصه المهني الظاهر من ملفه كأي مستخدم لكن **لقب «طبيب» لا يُمنح إلا بموافقة الأدمن** (يحميه trigger في قاعدة البيانات، لا الواجهة فقط).
- بعد موافقة الأدمن على طلب الطبيب يصبح لقبه «طبيب» ويُوثَّق تلقائيًا (علامة التوثيق).
- حسابات الأطباء المسجّلة قبل هذا التحديث تحتفظ بلقبها الحالي. إن أردت مراجعتها: من لوحة الأدمن ← **الاستشارات ← الأطباء** يمكنك **سحب** اللقب.

### رحلة الطبيب
1. من **للاستفسارات الطبية ← التسجيل كطبيب**: الاسم، السن، رقم التليفون الشخصي، الجامعة، رقم القيد بنقابة الأطباء، **صورة البطاقة** (رفع)، **صورة حيّة** تُلتقط من كاميرا الموقع مباشرة (لا رفع من المعرض)، والتخصص.
2. يصل الأدمن إشعار، ويراجع الطلب من **لوحة الأدمن ← الاستشارات ← الطلبات** (يرى الصور بروابط موقّعة مؤقتة) ثم **يوافق أو يرفض** مع ملاحظة تصل للمتقدم. بعد المراجعة يمكن للأدمن **حذف صور البطاقة والصورة الحيّة** من التخزين.
3. بعد الموافقة تظهر **لوحة الطبيب**: سعر الكشف (ضمن الحد الأدنى/الأقصى الذي يحدده الأدمن)، **مواعيد العمل** لكل يوم (يدعم أكثر من فترة)، مفتاح **نشط/غير نشط**، نبذة، وبيانات **استلام مستحقاته** (فودافون كاش أو إنستا باي). تظهر له حصته بعد خصم عمولة المنصة قبل الحفظ.
4. في كل حجز يرى شكوى المريض ويحادثه نصيًا ويضع **رابط اجتماع** (Google Meet/Zoom…، `https://` فقط) ويكتب **التشخيص**، ثم يضغط **إنهاء** بعد موعد الكشف.

### رحلة المريض (أي عضو غير الطبيب نفسه)
يتصفح الأطباء حسب **التخصص** (القائمة تحددها أنت)، يرى السعر والتقييم بالنجوم وحالة الطبيب (نشط الآن / غير نشط)، يختار يومًا وموعدًا من مواعيد عمل الطبيب، يكتب الشكوى، فيُحجز الموعد **30 دقيقة** (قابلة للتعديل) للدفع. يحوّل المبلغ لرقم المنصة (فودافون كاش أو إنستا باي)، ويكتب **رقم العملية** مع صورة الإيصال (اختيارية) ثم **«أرسلت التحويل»**. بعد التأكيد يدخل **غرفة الاستشارة** (محادثة + رابط الاجتماع + التشخيص)، وبعد الإنهاء يقيّم الطبيب (1–5 نجوم + تعليق).

### الدفع والعمولة — مهم أن تعرف كيف يعمل
- **المريض يدفع للمنصة** (وليس للطبيب مباشرة). فودافون كاش وإنستا باي **لا توفّران واجهة برمجية مفتوحة** لتأكيد التحويل تلقائيًا، لذلك التأكيد **يدوي**: الأدمن يراجع التحويل في حسابه ثم يضغط **تأكيد الدفع** (أو **رفض**).
- السعر والعمولة تُحسب **على الخادم** وقت الحجز: العمولة = `سعر الكشف × نسبة العمولة` (الافتراضي **30%**)، والباقي **صافي الطبيب**. تغيير النسبة لاحقًا **لا يؤثر على الحجوزات القائمة**.
- بعد إنهاء الاستشارة يظهر المبلغ في **«مستحق للأطباء»** عند الأدمن؛ يحوّله للطبيب على الوسيلة التي سجّلها ثم يضغط **«تم التحويل»** مع رقم العملية فيصل الطبيب إشعار.
- **الإلغاء والاسترداد:** المريض يلغي حجزه غير المدفوع بلا رسوم. إلغاء حجز أرسل عنه التحويل ولم يؤكَّد بعد يضع الاسترداد «مستحقًا»، وكذلك إلغاء حجز مؤكَّد قبل الموعد بأكثر من **12 ساعة** (قابلة للتعديل)؛ وإن كان أقل من ذلك فلا استرداد تلقائي (للأدمن تقدير الحالة وتسجيل استرداد يدوي). إلغاء الطبيب أو الأدمن يضع استرداد الحجز المدفوع «مستحقًا» دائمًا. الاسترداد نفسه **تحويل يدوي** يسجله الأدمن.
- ملخص الحسابات (المحصَّل، عمولة المنصة، المستحق للأطباء، المحوَّل، المطلوب ردّه) في **لوحة الأدمن ← الاستشارات ← المدفوعات**.

### ما يتحكم فيه الأدمن (كل شيء)
من **لوحة الأدمن ← الاستشارات**: تشغيل/إيقاف القسم كله، نسبة العمولة، مدة الموعد، أيام الحجز المتاحة، مهلة الدفع، الحد الأدنى للحجز قبل الموعد، مهلة الإلغاء المجاني، حدّي سعر الكشف، تفعيل/تعطيل **كل وسيلة دفع**، **أرقام استلام المنصة** (فودافون/إنستا باي)، **قائمة التخصصات** (إضافة/حذف/ترجمة)، تغيير تخصص أي طبيب، **إيقاف** طبيب مؤقتًا أو **سحب** صفته، إخفاء تقييم مسيء. وكل النصوص المكتوبة في واجهات القسم (مفاتيح تبدأ بـ `cs_` و`cse_` و`ac_`) قابلة للتعديل من **لوحة الأدمن ← النصوص** بالعربي والإنجليزي.

### التفعيل خطوة بخطوة (الوضع الحقيقي)
1. شغّل `supabase/schema.sql` ثم `supabase/storage.sql` (يمكن إعادة تشغيلهما على مشروع قائم؛ يضيفان ما ينقص ولا يمسّان البيانات).
2. سجّل دخولك أدمن ← **لوحة الأدمن ← الاستشارات ← الإعدادات**: ضع **أرقام استلام المنصة**، راجع **قائمة التخصصات** وعدّلها، ثم فعّل **«تشغيل القسم»** وأنقر حفظ.
3. اختبر الرحلة كاملة بحسابين (طبيب ومريض) بسعر تجريبي صغير قبل الإعلان.

### الخصوصية والأمان
- صور البطاقة والصورة الحيّة وإيصالات الدفع في حاوية **`private`**: لا قراءة عامة، ولا يقرأها إلا صاحبها والأدمن.
- **شكوى المريض والمحادثة والتشخيص** يراها **المريض والطبيب فقط — لا الأدمن**. (الأدمن يرى بيانات الحجز والدفع فقط.)
- لا يستطيع مستخدم تأكيد دفعه بنفسه، ولا قراءة حجوزات غيره، ولا الحجز في موعد محجوز (يمنعه الخادم، لا الواجهة فقط)، ولا الحجز عند طبيب موقوف أو غير نشط أو عند مستخدم بينهما حظر.

### تنبيهات قبل الإطلاق للجمهور
- **قانونيًا:** تقديم الاستشارات الطبية أونلاين وتحصيل مبالغ عليها يخضع لتنظيمات مصرية (وزارة الصحة/نقابة الأطباء/قانون حماية البيانات الشخصية 151 لسنة 2020). راجع محاميًا ومحاسبًا قبل التشغيل التجاري، وحدّث **سياسة الخصوصية** (`privacy.html`) لتشمل بيانات الأطباء وصور البطاقة.
- **الصورة الحيّة** رادع يقلل انتحال الهوية لكنه **ليس إثبات هوية قاطعًا**: قارن دائمًا مع رقم القيد في سجلات النقابة قبل الموافقة.
- الاستشارة النصية/المرئية **لا تغني عن الكشف الحضوري** ولا تصلح للطوارئ؛ تنبيه بذلك يظهر للمريض داخل القسم (ويمكن تعديل نصه).

## 11) حسابات الأنشطة التجارية + إعلانات بالكريدت

### عضو بلا تخصص طبي
عند التسجيل كـ **«عضو»** لا يظهر حقل التخصص الطبي أصلًا ولا يُحفظ (يُفرض `general` في قاعدة البيانات أيضًا). يظهر التخصص فقط لمن اختار صفة طبية (طالب/صيدلي/تمريض/أسنان).

### إنشاء حساب كنشاط تجاري
في نافذة إنشاء الحساب تبويب **«نشاط تجاري»** (اسم النشاط + نوع النشاط + المدينة). الحساب التجاري:
- ✔ ينشر منشورات، ويعلّق ويعجب ويشارك، وينضم للمجموعات، ويشتري الإعلانات.
- ✘ لا أصدقاء، لا وظائف (تقديم أو نشر)، لا سجل طبي، لا توثيق، لا مساعد طبي، لا استشارات، ولا إنشاء مجموعات.
- يظهر بجوار اسمه وسم **«نشاط تجاري»**، ولا يتغيّر نوع حسابه من جهته (والأدمن وحده يستطيع تغييره). هذه القيود مفروضة في قاعدة البيانات (RLS) لا في الواجهة فقط، ولا يمكن لأحد إرسال طلب صداقة لحساب تجاري.

### نظام الإعلانات بالكريدت
1. صاحب النشاط يفتح **إعلاناتي ← إعلان جديد**: عنوان ونص وزر ورابط `https://` ولون، ثم **عدد الكريدت** (حد أدنى **50** كريدت افتراضيًا). **سعر الكريدت الافتراضي 10 جنيه** (يعني 500 جنيه كحد أدنى للإعلان) ويرى المبلغ المطلوب لحظيًا.
2. يحوّل المبلغ **للمنصة** بفودافون كاش أو إنستا باي (أرقام الاستلام يضعها الأدمن في **الاستشارات ← الإعدادات** وتُستخدم للاستشارات والإعلانات معًا)، ويكتب **الرقم أو الحساب الذي حوّل منه** (إلزامي) ورقم العملية وصورة الإيصال (اختياريان).
3. يصل الأدمن إشعار، ويرى الطلب في **الأدمن ← الإعلانات ← طلبات الكريدت**: معاينة الإعلان والمعلن والمبلغ والوسيلة ورقم التحويل والإيصال، ثم **موافقة وتشغيل** أو **رفض** مع سبب يصل للمعلن. الإعلان لا يظهر لأحد قبل الموافقة.
4. بعد الموافقة يظهر الإعلان بين المنشورات. **كل كريدت = عدد مشاهدات يحدده الأدمن (افتراضي 100 مشاهدة)**؛ تُحتسب مشاهدات الأعضاء الآخرين فقط (مشاهدات صاحب الإعلان والأدمن لا تُحتسب). عند نفاد الكريدت يتوقف الإعلان ويصل صاحبه إشعار ويستطيع **شحن كريدت** (طلب جديد بنفس الخطوات) فيستأنف.
5. **الرفض أو إلغاء الطلب** يضع الاسترداد «مستحقًا»، والأدمن يحوّل المبلغ يدويًا ثم يضغط **«تم رد المبلغ»**. المعلن يستطيع **إيقاف إعلانه مؤقتًا واستئنافه** بنفسه. تعديل نص إعلان معتمد غير متاح (ينشئ إعلانًا جديدًا ليُراجَع).

### ما يتحكم فيه الأدمن
من **لوحة الأدمن ← الإعلانات ← إعدادات الكريدت**: **سعر الكريدت الواحد**، الحد الأدنى للكريدت في الإعلان، عدد المشاهدات لكل كريدت، وتفعيل/تعطيل كل وسيلة دفع. تغيير السعر **لا يؤثر على الطلبات القائمة** (سعرها مثبّت وقت الطلب). ويمكنه إيقاف أو حذف أي إعلان، ويرى ملخصًا (الكريدت المباع، المبيعات المؤكدة، المعلّق، الاستردادات المستحقة). وكل نصوص هذه الواجهات (مفاتيح `bz_` و`bze_`) قابلة للتعديل من **الأدمن ← النصوص**. مفتاح تشغيل الإعلانات العام (الموقع ← المزايا) يوقف شراء الإعلانات وعرضها معًا.

### الترقية لمشروع قائم
أعد تشغيل `supabase/schema.sql` (آمن: يضيف الأعمدة والجداول والدوال دون المساس بالبيانات) ثم أعد نشر دالة `ai` (`supabase functions deploy ai`) و`admin`. إعلانات الأدمن الحالية تبقى كما هي (بلا سقف مشاهدات).

### تنبيهات
- الدفع والاسترداد **يدويان** (لا توجد واجهة برمجية مفتوحة لفودافون كاش/إنستا باي). دوّن في الحسابات كل تحويل مؤكَّد.
- مبيعات الإعلانات دخل للمنصة: استشر محاسبًا بشأن الفواتير والضرائب، وراجع سياسة محتوى الإعلانات (خصوصًا الإعلانات الطبية والدوائية) قبل الموافقة عليها.
